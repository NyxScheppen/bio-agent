# Contributing to BioAI Agent

## Development setup

1. Create a Python 3.11 or 3.12 virtual environment.
2. Install `requirements-dev.txt`.
3. Run `npm ci` in `frontend/`.
4. Copy `backend/.env_example` to `backend/.env` only when live model calls are needed.
5. Install R packages with `Rscript install_r_packages.R` when changing an R-backed workflow.

Do not commit API keys, `.env` files, databases, user uploads, generated analysis files, local R libraries, or code-graph output.
`runtime/run_backend.bat` is generated by `start_app.bat`, contains machine-specific paths, and must remain untracked.

## Change expectations

- Keep tools deterministic where practical and return the shared `ToolResult` contract.
- Declare every executable tool in its Skill policy. Planned Skills must not acquire executable tool lists.
- Validate session ownership and storage paths before reading or deleting files.
- Update behavioral documentation when changing a public workflow or safety boundary.
- Add focused regression tests for bug fixes and run the broader suite when shared orchestration, storage, or tool contracts change.

## Required checks

```powershell
.venv\Scripts\python.exe -m compileall -q backend/app
.venv\Scripts\python.exe -m pytest -q backend/tests
.venv\Scripts\python.exe -m pip check

Set-Location frontend
npm run lint
npm run typecheck
npm test
npm run build
Set-Location ..

.venv\Scripts\python.exe scripts/verify_submission.py
git diff --check
```

Live external-service checks must state the date, endpoint, input, and exact blocked/failure status. HTTP 402 or quota exhaustion must be reported explicitly rather than generalized as a network failure.

## Pull requests

Describe the user-visible behavior, risk boundaries, tests run, and any environment-dependent validation that could not be completed. Keep generated data and unrelated formatting out of the change.

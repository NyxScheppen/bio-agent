# 文件上传、解析、存储与产物修复计划

## 目标

统一上传文件、工具生成文件和图片的标识、路径、资源预算与删除事务，消除路径穿越、跨会话引用、并发覆盖、部分写入可见、存储型主动内容执行和无界解析等问题。

## 边缘情况分析

### 会话和路径

- 空 ID、`..`、斜杠、反斜杠、超长 ID、首字符为下划线：拒绝，不做 basename 降级或静默改名。
- 显式引用其他会话的 upload/generated 路径：拒绝。
- URL 编码后的 `..`、绝对路径、盘符路径、符号链接逃逸：规范化后检查 storage containment。
- 带 session 的纯文件名查找：只查当前会话上传目录；不回退到 storage 根目录或其他会话。
- 模型只返回 basename：只在当前会话生成目录内查找，最多返回最近的三个同名结果。
- 临时上传和删除守卫：保留前缀在上传时拒绝，不允许通过 `/files` 下载，也不出现在上传列表。

### 上传和数据库事务

- 客户端伪造或省略 `Content-Length`：请求体中间件在 multipart 解析前按实际字节计数。
- 客户端伪造 `UploadFile.size`：服务层流式读取时再次检查单文件和批次上限。
- 同批第二个文件失败：回滚 session/file 数据库写入并删除本批已发布文件。
- 同名并发上传：完整写入隐藏暂存文件，再用同卷硬链接以“不覆盖”语义原子发布唯一名称。
- 写入尚未完成：最终 URL 不存在；只能看到不可下载的隐藏暂存名。
- 数据库提交失败：上传清理已发布文件；删除操作移除守卫，原文件名在事务期间始终存在。
- 文件名含目录、Windows 保留名、内部临时前缀、控制字符或超长 UTF-8 名称：规范化或拒绝。

### 下载和展示

- HTML、SVG、XML、JavaScript、CSS：以 `application/octet-stream` 和 attachment 返回，并设置 `nosniff` 与 sandbox CSP。
- PNG/JPEG 等普通图片：保持正常 MIME，允许前端展示。
- storage 外路径、不存在文件、临时文件和目录：统一 404。
- URL：后端返回带百分号编码的相对 `/files/...`，不硬编码主机和端口。

### 解析和预览

- 大 CSV/TSV：超过扫描预算时仍可返回有限预览，但总行数为未知。
- gzip 高压缩比数据：解压计数超过预算立即停止，不遍历完整内容。
- 单行超长 CSV/文本：在交给 pandas 前拒绝，避免单字段内存膨胀。
- XLSX zip bomb：构造 `ZipFile` 前以常量内存校验中央目录条目预算，再累计 member 的未压缩大小并拒绝超限文件。
- `.xls`：应用压缩文件大小上限；无法像 XLSX 一样预检 ZIP member。
- 非 UTF-8 文本：预览用替换字符解码，不因单个坏字节崩溃。

### 生成文件和图片

- 每次生命周期执行使用 `generated/{session_id}/{job_id}/`，并注入 `job_dir`。
- 工具声明不存在、其他 job 或其他 session 的产物：生命周期丢弃。
- 工具声明伪造 `name`、`type`、`url`：用实际文件路径、扩展名和大小重建。
- 文本回复包含跨会话路径或 `generated/../uploads/...`：不解析成附件。
- 前端伪造附件：只有当前会话下实际存在的 upload/generated 文件可进入 Agent 上下文。
- R 模板输入包含引号、反斜杠或换行：作为 R 字符串转义；公式列名使用严格标识符白名单。
- R 预处理模式：使用枚举，不允许任意文本进入脚本模板。
- 任意 R 代码：不作为 Agent 工具注册；模板防护不宣称是 OS 沙箱。

### 删除和历史兼容

- 只清理 generated：保留会话、消息、上传文件和上传记录。
- 完整删除：先为实体创建同目录硬链接守卫且保留公开路径，数据库提交成功后校验实体身份并删除；回滚只移除守卫。
- 实体文件缺失：删除失效数据库记录。
- 数据库记录指向其他会话路径：无其他引用时中止，不删除记录或文件。
- 旧数据中多个会话共享同一路径：只删除当前会话记录，保留实体文件。
- 升级前的 `generated/<job_id>/<file>` 无共享生成物：允许随当前会话删除。
- 删除守卫最终清理失败：数据库已经提交，结果显式报告清理失败，不伪装成完全成功。
- API 不做目录级递归兜底删除，避免绕过数据库共享引用判断。

## 实施顺序

1. 建立共享 storage contract：会话 ID、文件名、相对路径、会话所有权、主动内容类型。
2. 在 multipart 解析前增加请求体上限，并在流式持久化阶段再次执行文件数、单文件和批次预算。
3. 采用隐藏暂存文件、刷盘和原子发布，建立上传批次的数据库/磁盘回滚。
4. 以受控 `/files` 路由替换 storage 静态挂载，限制根目录并为主动内容强制下载。
5. 将生成物统一放入生命周期 job 目录，只接受当前 job 中实际存在的输出。
6. 限制聊天附件、文本兜底和文件解析器到当前会话所有权范围。
7. 对 R 模板字符串、列名、数值和枚举参数做结构化校验，并把 job 目录传给所有生成型工具。
8. 为 CSV、gzip、Excel 和单行内容增加预览预算。
9. 用硬链接删除守卫协调文件删除和数据库删除，区分 generated-only 与完整会话删除。
10. 增加并发、回滚、穿越、主动内容、压缩炸弹、模板注入和历史共享路径测试。

## 验收标准

- 所有可持久化路径均在解析后验证 storage containment 和会话所有权。
- 上传请求在 multipart 解析前有硬上限，在文件流阶段有独立二次上限。
- 并发同名上传不覆盖，最终名称在完整写入前不可见。
- 批量上传和删除在数据库失败时可恢复磁盘状态。
- `/files` 不提供临时文件，主动内容不能以内联可执行 MIME 返回。
- Agent、工具和回复文本不能声明当前 job/session 外的产物。
- 大表、gzip 和 XLSX 预览有可配置资源上限。
- generated-only 清理不会删除会话或上传；完整删除不会误删跨会话文件。
- 新增边缘测试与完整后端测试全部通过。
